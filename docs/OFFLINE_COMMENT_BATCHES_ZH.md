# 离线评论后台分批修复（2.0.99）

## 最新用户要求

净化设置及直播上下滑动限制已由用户反馈“可以了”，按本轮反馈验收通过。离线评论恢复处理：多次重新下载后仍只有开头几个视频有评论；用户通常开始下载后回主页，不会逐个打开离线视频，也不能依赖推荐流再次刷到相同视频。

用户要求分批处理，翻译参考字幕逻辑，并检查与离线视频保存类似的落盘／读取问题。所有进度只在设置中主动查看，播放页面不增加弹窗、浮窗、提示条或自动通知。

## 已确认的代码问题与修正

- 旧完成回调在代码核验尚未结束时直接返回，可能丢掉任务。新增待登记队列；按视频身份去重，核验后每批最多5个视频登记。
- 旧单线程同时登记视频、等待评论请求和逐条翻译；一条慢请求会延迟后续登记。拆为独立的登记、原文／回复、翻译通道。原文分页完成后独立推进，不等待该页所有译文。
- 原文和译文各自保存进度与重试时间。翻译复用字幕的原生翻译通道及长文本分段器，优先利用已有译文；每条成功结果按评论身份及原文匹配写回持久档案。
- 每轮最多处理5个视频，优先让尚无首批原文的视频取得首批数据，再轮流补全后续分页和回复。首批原文不等于全部缓存就绪；只有原文、回复、当前语言译文均齐备才标完成。
- 旧任务失败三次后可长期停止。改为独立通道的有界退避、明确下一次唤醒时间，并在连续网络失败时放缓该通道；不会清空已成功的原文或译文。
- 原文与翻译的持久任务更新按字段合并；源数据版本和账号清理代次阻止旧完成覆盖新工作。沿用现有档案目录和任务存储，保留旧文件及已下载视频。
- 离线读取始终尝试恢复已有译文；档案损坏时保留原生／持久快照回退，不因状态读取失败而丢掉可显示结果，也不据此覆盖正常档案页。

## 评论入口与错误证据

普通离线评论按钮仍使用已检查的专用按钮适配，不全局劫持点击，不依赖主页偶遇。后台以原生下载完成回调和用户已启用的离线列表补缓存为来源；已有视频可直接补缓存，无需重新下载媒体。

已从保留的原宿主目标DEX核实，旧日志中的同类异常是网络IOException包装，提供HTTP状态码和网络引擎错误码；此前只有类型名，不能确定具体网络失败原因。新增诊断只保存阶段、异常类型链和数字错误码，不保存错误消息、请求日志、URL、正文、账号或凭据。当前没有设备连接，尚无本轮实际状态码，也没有证据要求改掉原生评论请求场景，因此不盲目切换请求入口。

## 安静的状态入口

Toki设置→离线视频→查看离线评论缓存状态。仅主动打开或点击刷新时读取已有报告；不会启动宿主或触发评论／翻译请求。显示已登记视频、首批原文、完整原文及回复、原文及译文全部就绪、等待重试和待登记数量。管理端沿用已有签名权限保护的只读诊断协议；宿主内设置可直接读取本进程计数。

## 验收边界

82项定向测试、799项源码检查、564份生产输入及统一包／载荷校验通过；60视频用例为模拟数据。验收需覆盖整批已下载视频、下载后回主页、断网重开、账号隔离、原文及译文和回复分页。前几个视频可用不算整批通过。测试、包体和实际设备证据分别记录；不以源码检查替代手机验收。

本轮不修改手机开关、不重新下载视频、不自动安装或重启，不执行手动清空全部离线视频的破坏性测试。HDR继续停止。
