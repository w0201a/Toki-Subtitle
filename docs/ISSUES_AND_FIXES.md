# 问题、修复与验证记录

维护范围：Toki 字幕版。原作者为 [MeiYongAI](https://github.com/MeiYongAI/Toki)，字幕版由 **154Er · Gi-Ai154M** 维护。

本页是经过整理的公开问题记录，不上传原始设备日志、视频正文、用户截图、API 凭据或宿主反编译内容。版本改动见 [CHANGELOG](../CHANGELOG.md)。

## 未发行：字幕语言、普通显示、清屏及样式继续解耦

继续检查字幕实现后发现剩余连带依赖：排除语言读取与目标语言在同一事务内，后者即使安装成功也会因排除列表失配而撤销；设置菜单在渲染解析后安装；清屏帧契约在普通显示钩子前解析；关闭字幕样式会同时停止本地字幕翻译。本轮逐项拆开，普通显示增加经宿主控件创建边界登记渲染器的路径，保留对字幕容器身份的核验，不扫描无关页面文字作为字幕。

显示依赖的控件绑定及清屏监听在显示通路失败时一并释放，避免保留可写失效显示层的监听；独立目标语言和菜单不受其影响。翻译器创建后立即登记释放，避免后续反射失败留下工作线程。取消评论翻译开关对视频字幕目标语言的交叉作用。

仅开视频翻译、关闭字幕样式时，译文仍显示。样式关闭不应用自定义字号、颜色、位置和拖拽；对字幕源子树最多检查 32 个控件，唯一正文匹配的原生 TextView 可提供字号、字体、颜色和纯色背景，否则使用显示层默认样式。原生字幕文字和播放器层级不变。关闭视频翻译后恢复原字幕显示，不能将其解释为原生布局完全复刻。

验证包括真实注册替身：只有目标语言契约存在、排除列表／菜单／渲染缺失时，目标语言钩子仍保留；显示撤销会释放依赖监听但保留独立语言通路；关闭样式时译文更新且原生字号颜色保留，关闭翻译后恢复源层。未进行新的 ADB 读取或手机画面验收，宿主未解析入口仍不保证恢复。本轮仅提交源码文档，不创建发行或标签。

## 未发行：字幕优先、后台适配和多核分析

按用户要求，本轮仅提交源码和文档，不创建标签或发行版本，不上传 APK。最终本地完整 573 项测试通过；Debug 构建与 lint 通过，lint 为 0 错误、29 项警告。构建通过不表示已完成手机最终画面验收。

新诊断包同时含 2.0.22 旧快照和 2.0.23 新快照，分析采用最新快照。2.0.23 的保存、页面净化与信息流主通路已保留，字幕仍在注册阶段失配：策略方法、渲染入口、目标语言分别失败；标题请求及译文布局已有成功记录，不能把它当作视频字幕已成功。

优先增加独立的原字幕保留通路：对经精确签名及视频／翻译覆盖／原帧布尔行为核验的隐藏判定，在模块翻译开启时保留原帧和基础状态，译文帧继续遵循宿主。此通路不依赖字幕显示、策略或结果服务整体安装成功。策略跳过和隐藏辅助入口各自可选，缺失不撤销其他读入口。它不会生成视频本来没有的字幕；本轮仍无手机最终显示验收。

字幕渲染通过已核验帧的状态字段恢复演化枚举，允许模式类型改为具名类型及渲染方法增加尾部参数；必须保留已证明的前部角色、调用关系和完整实际签名，不能凭同名或同签名任意挂钩。

多核分析共享只读 DEX，方法指纹与方法行为并行计算，调用关系按最多 128 类的有界批次计算，结果按输入顺序归并。线程上限取可用 CPU、8 和可用堆内存预算的较小值，少量工作保留串行以避免线程调度成本。测试验证四个工作线程确实同时参与、顺序确定与异常传播。256 MB Java 堆的同一离线 APK 单次样本：1 线程 51,463ms、4 线程 30,114ms，35 类匹配且全部输出相同。不同阶段可能受 I/O 或串行工作限制，不承诺 CPU 始终满载，也不代表手机已实测该速度。

适配窗口采用非模态触摸标记，用户可点击窗口外继续操作；「后台适配，继续刷视频」仅收起进度，不结束任务。完成、部分成功或失败会在宿主前台给出 Toast；宿主在后台时，回到前台后处理提醒。测试覆盖收起后阶段仍为扫描、完成后不弹阻塞窗口以及提醒出现。没有新增系统悬浮窗或通知权限。

## 2.0.23 Debug：版本切换后的多功能注册失败

用户本地导出的 2.0.22 诊断表明，多项功能在注册阶段失配，不是单纯的字幕网络延迟：字幕轨补偿的服务结果方法、字幕显示所需模式类、字幕语言方法、评论入口、评论复制契约、自动滚动页面上下文、保存备用 Getter、页面组件以及信息流离线开关分别失败。原始包、正文、日志和设备信息不入库，亦未通过 ADB 读取。

针对已确认的连带问题：保存备用地址方法只保留存在且返回类型正确的入口，选源与 ACL／路径独立；布局组件按成员逐个核验，缺失不撤销其他组件；信息流离线恢复、推荐数据模型与适配器独立事务；自动滚动入口和页面行为拆开。字幕渲染增加按完整已核验方法描述符解析的路径，避免参数类型角色缺失阻止已验证成员；没有完整方法证据时仍拒绝安装。父功能部分成功会继续显示部分状态，而不会报告全部功能正常。字幕结果／轨号／缓存服务读入口分别使用可用契约。

基础适配新增独立的本地完整核验：原生快速筛选异常或零候选后，对缺失符号重跑严格契约；不会放宽到只看方法签名，也不会覆盖之前成功的目标。恢复算法修订只使旧失败结果重新核验，已成功目标保留。字幕语言直接从精确的语言偏好键及 Keva 调用定位；普通评论方法数量变化时，仅选取有供应者、惰性值、布尔拆箱与直接调用证据的方法。三版已保存 APK 的字幕语言与普通评论规则离线通过，不能视为用户新代码集合真机效果验证。

**尚未确认恢复**：用户本轮代码集合中的字幕模式类／显示与清屏、评论复制关系、自动滚动页面路由，以及所有功能的最终手机效果。完整本地核验能排除快速筛选漏选，但无法凭空恢复没有行为证据的新实现。这些项仍需维护业务识别规则；本轮交付不声明全部修复。

## 2.0.22 Debug：异步提前准备后续视频

用户明确要求看到字幕时译文已准备好，并支持连续快速切换，优化不能仅停留在当前句请求速度。新增两条有界字幕文件下载通道；从已加载的真实推荐列表读取后四个位置，轮流预翻译每条开头六句。当前邻近三句优先，随后轮询后续视频开头，再处理当前剩余预读，最多 32 个候选句；译文内存缓存最多 256 条，切换后复用已完成结果。未找到当前时间轴句时，后续已取得的时间轴仍可进入准备队列。

补齐只开启字幕时的推荐列表依赖，避免其依赖信息流过滤功能是否启用。当前句和预读的发送时机分开：预读刚发送时不会扣住当前句 250ms；当前句之间仍节流，翻译请求仍最多两条。没有通过无限并发增加接口负担。代次检查继续拒绝旧视频迟到结果。

验证包括四条开头交错排程、真实列表位置边界、未找到当前句时的后续准备、重复字幕去重、当前句不受预读节流阻塞，以及四条已完成译文连续切换不产生新请求。上述是程序调度与缓存测试，没有实测手机网络耗时。仍需要宿主已加载后续条目、可用字幕轨和翻译服务成功返回；不保证无限连续滑动或所有视频开头都已完成，更不等于整段视频字幕都已译完。

## 2.0.21 Debug：长文案显示与字幕等待

用户反馈长文本没有翻译、字幕翻译不及时，并强调修复应面向自动适配，不能依赖用户提供版本号或 ADB 日志。检查代码发现：长文案原本等全部分段完成才提交，单段失败没有自动重试；标题控件若在绑定过程中创建或替换，布局关联可能没有记录；字幕失败退避时间存放在共享调度字段，之后的新句会继承等待。

修复为成功段立即显示、未完成段保留原文，失败段排到其他分段之后最多重试一次；绑定后记录最终控件；字幕退避改为失败任务自身的时间，只影响该句重试。投票默认继续原来的失败行为，不因长文案重试开关而改变。保留两条字幕请求通道及最小请求间隔。

定向回归覆盖失败分段后的其他段显示、有限重试、旧视频迟到结果、新字幕不继承旧句退避和预读调度。Debug 构建、翻译定向测试、版本代码身份／规则／重试请求的缓存失效测试通过，lint 为 0 错误、28 项警告。未进行新的 ADB 读取或手机画面验收。这些是调度和显示缺陷的修复，不能据此声称所有未来宿主的类与接口变化均能自动解析。正常宿主升级、降级仍自动核验实际代码身份。

## 2.0.20 Debug：普通评论翻译入口失配（包含 2.0.19 修复）

用户反馈评论没有翻译。检查已有 47.1.16 数据和代码后确认：基础 COMMENT_TRANSLATION 整体指纹未匹配，而评论自动翻译的偏好和调用图仍存在；旧实现只尝试基础指纹，因此未安装普通评论入口。评论投票使用另一条独立通路，不能用投票状态代替普通评论状态。

新增手机内关系分析：查找包含 `comment_auto_translation_enabled` 且装箱布尔值的供应者，再核对创建供应者的惰性值初始化、对应字段读取、布尔拆箱和三个开关方法间的调用。只接受唯一完整关系，保留旧结构核验路径；未知类名由当前手机代码产生，不写死 47.1.16 混淆类名。状态页增加「普通评论翻译入口」，算法修订自动使旧扩展缓存重新核验。

2.0.19 完整 552 项测试通过，但最终 lint 发现 Stream.toList 需要较新 Android API；2.0.20 改用兼容收集方式，并重新执行评论规则测试、Debug 构建和 lint。2.0.19 预览标注为已被替代，不推荐安装。

192 MB 堆下，47.1.16 离线扫描恢复评论入口；46.9.3 与 47.4.3 也通过同一关系解析。代码测试覆盖供应者变化和调用关系断裂的拒绝。以上属于接口分析与构建验证，尚未验证手机中普通评论译文最终显示，不能宣称所有评论场景修复。整个运行流程不依赖 ADB、电脑生成的缓存或外部适配服务。

## 2.0.17 / 2.0.18：手机独立适配

正常使用时由手机读取已安装 TikTok 的基础包与 Split，在代码身份变化后自动失效旧结果，后台分析并核验接口，再在当前进程安装可用功能。新版本和降版本采用同一流程，不依赖电脑、ADB、上传宿主文件或外部适配服务。

| 路径 | 自动分析依据 | 失败后的行为 |
| --- | --- | --- |
| 结构匹配 | 类继承、接口、方法、字段及完整指令指纹 | 继续独立关系分析 |
| 业务引用关系 | 有序调用与字段引用，忽略寄存器及指定插桩差异 | 拒绝歧义，继续专项规则 |
| 专项契约 | 字幕帧和渲染器、语言偏好、翻译服务与订阅、投票桥接及生命周期 | 只撤销对应注册事务 |
| 本地分析降级 | 原生筛选不可用时直接分析本机 DEX | 不依赖外部处理 |

Toki「功能状态监控」显示各条翻译通路的注册状态；注册正常代表接口就绪，不保证每条内容均有字幕或每次网络翻译成功。手机内的「重新检测适配」会保存请求，完全关闭并重开 TikTok 后重新分析，不清除用户数据。正常更新、降级不需要先点击该按钮。确定未匹配的结果会缓存，避免每次启动无意义地重复扫描；宿主代码、规则或重新检测请求变化时重新核验。

验证记录：2.0.17 Debug 的 548 项单元测试及 Debug 构建通过，lint 为 0 错误、28 项警告。离线分别检查 46.9.3、47.4.3 与 47.1.16 的必要翻译契约；当前 47.1.16 的字幕菜单仍有独立字段未解析，主要翻译所缺私有读入口已改为可选或替代接口。优化后电脑单次离线分析约 27、34、37 秒，不能当作手机性能数据。

真机已覆盖安装 2.0.17 Debug，并确认冷启动自动进入手机本机扩展分析；没有向手机注入电脑生成的缓存。连接结束前未取得分析完成结果；用户随后在手机确认扫描已结束并提示部分适配。当前 47.1.16 的具体缺失项、字幕／清屏／标题／投票画面，以及投屏兼容开关仍未完成实机验收。2.0.18 是之后补齐本机降级和分项状态的 Debug 更新，应从 APK 在手机安装。此记录不会把离线匹配或扫描已开始解释为真机效果已经修复。

2.0.18 最终 Debug：551 项单元测试全部通过，lint 为 0 错误、28 项警告，APK 已构建。此验证不替代手机最终显示效果验收。

针对用户反馈的「字幕扩展长时间等待」，进一步修正候选类持有整个 DEX 数据的内存占用；只保留已接受候选的独立数据，并按 ZIP 长度直接分配单个读取缓冲。192 MB Java 堆上对 47.1.16 的离线分析完成，仍为 35 个类、521 个未解析参考契约；一次样本约 41 秒，保留主要翻译接口。这是受限内存的电脑验证，不是手机耗时或最终画面验收。扫描器内存耗尽会报告失败；其他不可恢复的虚拟机错误仍传播。

扩展分析窗口现在区分原生筛选、结构分析、调用关系与接口核验，并显示当前阶段的实际 DEX 处理数；不会把基础扫描的 100% 沿用到扩展阶段。基础功能可在扩展分析结束前独立安装；字幕菜单与其他翻译通路独立报告部分失败。

大幅改写、缺少业务证据或出现多个候选仍可能需要模块更新；自动适配不是对所有未来接口的保证。原作者、上游链接及许可证保持保留。

## 2.0.16 自动适配机制

- 基础功能沿用现有 DEX 发现；字幕扩展单独按完整代码集合、结构配置摘要和格式版本缓存，宿主更新或配置变化后重新查找。
- 匹配类形状、方法指令与控制流、字段使用位置。较大的混淆类允许无关方法变化，但至少 8 个方法且不少于双方方法数的 60% 必须保持一致，并验证继承关系；实际使用的每个成员仍需独立证据，不能仅凭类相似就挂钩。
- 相同签名的抽象接口使用独立调用位置或具体服务实现的指纹补充证据。字段可由其他类中未变化的读写位置识别。多个候选、多个角色占用同一个类或证据冲突时拒绝匹配。
- 评论投票通过真实 `onBindItemView` 桥接调用定位绑定方法，并交叉验证标题到 `setText`、选项正文到 `setOptionLabel`、绑定与更新共用的选项排序方法和控件列表。标题渲染通过已核验视频字段的唯一写入入口定位；字幕帧入口必须读取已核验的文本与状态字段，并调用已核验的渲染器。
- 翻译开关规则在保留寄存器、控制流和实验配置链接证据的前提下容忍混淆调用名变化。47.0.3 与 47.4.3 的这组语义摘要相同，无需为新版另填入口名称。
- 字幕、字幕轨补偿、长文案与评论投票保留独立注册事务；匹配失败不再撤销基础翻译。扫描失败可记录扩展不可用，基础扫描结果仍能保存。
- 未知版本首次运行需要等待后台发现；保存并核对后在主线程自动安装已匹配的功能，切换视频刷新已有内容，无需连接电脑或再次重启。匹配不等于完整画面验收；新版字幕、清屏、长文案和评论投票仍需实机回归。
- 维护者可用 `scripts/GenerateExtensionProfile.java` 和本地授权参考 APK 重新生成结构配置；配置只包含摘要、类型及成员描述，宿主 APK 和反编译内容不得提交。

### 减少重复修复的验收流程

1. 宿主更新自动使旧代码缓存失效；后台扫描完成后自动应用已验证入口，之后复用本机验证结果。模块规则升级时逐项保留未变化的基础结果，只补查变化依赖。
2. 翻译开关、字幕轨补偿、字幕显示、原生标题翻译、标题布局补偿与评论投票分别注册。某一入口失配时记录具体契约，其他入口继续尝试安装。
3. 开发阶段先离线扫描实际宿主安装包，检查字幕、清屏帧入口、标题布局、投票绑定和翻译传输依赖，再构建一次候选 Debug。单元测试覆盖改名、局部变化、歧义拒绝、桥接与字段关系，以及规则变化后的缓存复用。
4. 真机验收分成“适配结果完整”“挂钩实际注册”“译文实际显示”三层。集中检查普通字幕、清屏字幕、长文案与评论投票；仅请求成功或挂钩成功不能判定画面修复。
5. GitHub 默认只测试并构建 Debug；手动工作流明确选中 Release 才额外构建。未来宿主完全更换翻译服务、字幕通道或 UI 框架时仍可能需要维护规则，自动匹配不代表保证所有未来版本兼容。

“100% 后长时间等待”曾由基础扫描进度未切换到字幕扩展阶段引起。现在扩展使用独立提示，不沿用基础扫描百分比；只有保存与回读核对成功才显示完成。同时收紧原生候选筛选和字段证据的指令检查范围。未改变宿主代码、适配规则和参考配置时复用缓存，不应反复扫描。

2026-10-19 在 47.4.3 真机确认：基础扫描后显示“正在适配字幕扩展”；扩展缓存已保存，随后启动直接复用。字幕、字幕轨补偿、标题布局补偿、评论投票已注册，诊断记录标题译文写入布局。原生标题资格入口仍有独立契约未匹配，使用标题布局补偿；这不代表所有视频、清屏场景和投票画面均已验收。进一步加入方法数量和继承结构预筛选，离线扫描耗时约 13.4 秒，仍为 46 个类、380 个未解析成员；未解析成员包含参考类中未使用的成员，不能将类匹配数视为所有功能通过。

后续在 46.9.3 验证自动补偿：首次基础与扩展发现约 75 秒；补偿规则升级后的扩展重新发现约 49 秒，其中原生候选为 62,403 个。以上是当前设备单次样本，不同代码集合及设备不能直接作速度比。扫描、保存核对、功能自动注册均在同一宿主进程完成；字幕显示、字幕服务补偿、原生标题资格、标题布局补偿和评论投票均已注册，原生文字翻译通道已就绪。私有选择器和缓存读入口失配时保留已核验服务路径。仍需按实际内容核对普通字幕、清屏与投票的最终画面，不能仅凭注册成功宣称所有内容均正常。

本轮完整 537 项测试通过；Debug 构建与 lint 通过，lint 为 0 错误、28 项警告。资源目录包含全部提示键，尚未新增翻译的语言使用英文提示。自动适配在手机本地运行，电脑只用于开发验证。大幅重写或证据不足的宿主入口仍会保留原行为并记录诊断，不以任意挂钩代替适配。
